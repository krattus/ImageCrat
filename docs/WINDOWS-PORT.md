# ImageCrat for Windows: porting plan

Status as of 2026-10-05: the portable core library `ImageCratCore` **builds and passes its unit tests on Windows 11 on Arm** (Swift 6.3.3, in the dev VM), and a first Windows program, **ImageCrat Preview** (a Win32 viewer, technical preview), ships as x64 and arm64 installers. Everything below the "Done" section is the plan.

## Why this is a port and not a recompile

ImageCrat is about 186,000 lines of Swift. The app's own logic is mostly plain Swift, but everything it shows or computes on the GPU sits on Apple-only frameworks.

| Area | macOS today | Size of the dependency |
|---|---|---|
| Interface | SwiftUI + AppKit | about 440 views, 81,800 lines of SwiftUI code, 52,000 more lines that use AppKit |
| Rendering | Core Image + Metal | 114 built-in Core Image filters (382 uses), 164 custom kernels, 5 Metal shaders |
| 2D drawing | Core Graphics | `CGImage` used 1,178 times, `CGContext` 208, `CGPath` 182 |
| Text | CoreText; `NSTextView` for on-canvas editing | 139 uses in 18 files |
| On-device AI | Core ML, Vision, MLX (SAM 3.1), Create ML | 10 downloadable models, 20 Vision request types |
| Files and system | ImageIO, PDFKit, ColorSync, Keychain, pasteboard, printing | spread over about 60 files |

## Target architecture

1. **Shared Swift core (`ImageCratCore`).** The document model, file formats, history and algorithms. It uses only Foundation, so it builds on macOS, Windows and Linux.
2. **Portable render engine, used on macOS too.** This means one code path, and identical output on both systems.
   - A lazy, tiled filter graph that only computes the regions needed, running WGSL compute shaders through wgpu or Dawn: Metal underneath on macOS, Direct3D 12 on Windows.
   - Skia for 2D rasterisation, gradients and PDF output.
   - Estimated about 210–230 shaders. About 160 of them can come from a mostly mechanical translator from Core Image's kernel language to WGSL.
3. **AI models through ONNX Runtime:** the Core ML provider on macOS, DirectML or Windows ML on Windows. Every model has an ONNX version except two:
   - SAM 3.1 on MLX stays Mac-only, or moves to SAM 3 in ONNX.
   - Style Transfer trains on the device with Create ML, which has no Windows counterpart. It would be replaced by a ready-made "any style" model (AdaIN).
4. **Text through HarfBuzz + ICU on both systems** (with FreeType or Skia for glyphs), so type lays out identically on Mac and Windows. This also means writing a custom on-canvas text editor.
5. **Platform services behind one interface.** Each Mac service maps to a Windows one:

   | Service | macOS | Windows |
   |---|---|---|
   | Files and dialogs | macOS dialogs | Windows file dialogs |
   | Clipboard | pasteboard | Windows clipboard |
   | Drag and drop | AppKit | OLE |
   | Printing | macOS printing | Windows printing |
   | API keys | Keychain | Credential Manager |
   | Fonts | CoreText | DirectWrite |
   | Text recognition | Vision | Windows OCR |
   | Video | AVFoundation | Media Foundation |
   | Scripting | JavaScriptCore | QuickJS |

   Each file format also needs a Windows library:

   | Format | Library | Licence |
   |---|---|---|
   | HEIC | libheif | LGPL |
   | Camera RAW | LibRaw | |
   | PDF rendering | PDFium | |
   | Colour management | Little CMS | |
   | SVG fallback | resvg | |

   Avoid AGPL and GPL libraries.
6. **Interface:** keep SwiftUI on macOS. On Windows, build a WinUI 3 interface in Swift through swift-winrt, with the canvas in a `SwapChainPanel`. If the Swift WinUI path proves too immature, the fallback is a C# WinUI interface talking to the Swift core over a C interface.

## Phases

Relative effort: Phase 0 = 1 unit, about 3–4 weeks of focused work.

| Phase | Work | Effort |
|---|---|---|
| 0 | Spike on real Windows hardware: a WinUI window in Swift showing a two-layer document rendered by a small WGSL graph (blur, morphology, guided filter, blend modes, 5 translated kernels); pixel comparison against Core Image; SAM 2.1 + LaMa through ONNX Runtime | 1 |
| 1 | Portable core on macOS (**first part done**, see below); platform-service interfaces; take Core Graphics drawing and `CGPath` out of the core | 3 |
| 2 | Portable render engine on macOS behind a switch, matched against Core Image with the existing self-tests | 5 |
| 3 | HarfBuzz/ICU text engine and custom text editor | 2 |
| 4 | AI models through ONNX Runtime | 2 |
| 5 | File formats and system services | 2 |
| 6 | Windows interface: panels, menus, dialogs, canvas input | 5–6 |
| 7 | Packaging (MSIX), signing, performance and QA on real hardware | 1–2 |

## Biggest risks
1. Matching Core Image's look and speed. The hardest are Noise Reduction, Bokeh, the guided filter, RAW development, and Core Image's half-float tiled pipeline.
2. Swift's interface tooling on Windows is young. swift-winrt bindings must be generated by hand, and Swift 6.4's package tool crashes on Windows on Arm, so stay on 6.3.x.
3. **A VM can't test GPU or AI work.** Parallels, VMware and UTM give Windows on Arm no Direct3D 12, so filters and models fall back to the CPU. The VM is for compiling and interface work. Rendering and AI need a real Windows PC with a graphics card.
4. Code signing for an individual outside the USA and Canada. Azure Artifact Signing isn't open to them, so the options are the Microsoft Store (free, re-signed by Microsoft) or an OV certificate.
5. HEVC patents for HEIC export; LGPL libraries must ship as separate DLLs.

## Done

### Step 1: `ImageCratCore`

- **What it is:** a new SwiftPM library at `Sources/ImageCratCore`, 54 files and about 11,500 lines of code. It holds:
  - geometry, colour and blend modes;
  - vector paths;
  - layer effects;
  - the layer and document model and `PixelBuffer`;
  - adjustment and filter settings, and the Recipe graph model;
  - inpaint and content-aware scale, the puppet-warp deformer, and particle data;
  - the ABR brush importer and the PDF lexer;
  - the byte-level PSD reader and writer: sections, layer records, descriptors, layer styles and adjustment blocks.
- **The Mac app's side:** the app plugs its Core Graphics, Core Image and Metal parts back in from `Sources/Lumen/CoreBridge` (`CorePlatform.install()` runs first at launch). Its behaviour and speed are unchanged: all self-tests pass, and the perf test is within noise.
- **Guard:** `scripts/check_core_portable.sh` fails on any Apple-only API in the core. It stands in until a real Windows or Linux CI build exists.
- **Tests:** `swift test` runs the `ImageCratCoreTests` unit tests. These are the first tests that will run on Windows too.
- **Known gap:** on Windows and Linux the core can't yet read pixels in documents saved by the Mac, which are LZFSE-compressed. It needs a portable LZFSE decoder.

### Development VM

- **Setup:** UTM, a "Windows 11 Dev" VM running Windows 11 Pro on Arm, with 16 GB of RAM, 8 cores, 128 GB of disk, TPM and Secure Boot.
- **Build tools:** `setup.ps1` installs Git, Visual Studio 2022 Build Tools (Arm64 and x64 C++, Windows SDK) and Swift 6.3.3, and enables SSH from the Mac with a key only.

### First Windows build (2026-10-05)

- `Package.swift` declares only `ImageCratCore` and its tests when not on macOS, so the same checkout builds on Windows.
- **Build:** `swift build` on Windows needed one fix (an `@inlinable` method in the `CGAffineTransform` stand-in).
- **Tests:** `swift test` runs **62 tests, 0 failures**. The 63rd, which compares the stand-in with CoreGraphics, only runs on the Mac. That covers the document model and `PixelBuffer`, PSD byte read/write, the brush formats (ABR, GIMP, Procreate, Krita, `.icbrushes`, zip, inflate/deflate, PNG), inpaint and content-aware scale, and the stroke and pressure maths.
- **From the Mac:** `scripts/test_core_windows.sh` copies the core into the VM, builds it and runs the tests.

### Technical preview: ImageCrat Preview for Windows (2026-10-05)

A first Windows program to try the core on real PCs. It only views files; nothing of the Mac app's UI, rendering or AI is
ported yet.

- **`ImageCratPreview.exe`** (`Sources/ImageCratPreview`): a Win32 GUI in Swift on `WinSDK` only (no UI framework).
  - Opens `.psd`/`.psb` (the composite stored in the file; layer list with groups, kind, visibility, blend mode,
    opacity, effects and thumbnails), `.png`, and brush files (`.abr`, `.gbr`, `.gih`, `.brush`, `.brushset`, `.kpp`,
    `.icbrushes`) as a grid of tips.
  - Zoom and pan over a checkerboard, rendered in software into one DIB per paint (premultiplied mip levels, bilinear
    below 100 %), so it is flicker-free. Per-monitor DPI aware, common controls 6 through an embedded manifest.
  - Help ▸ Run Self-Check runs the built-in battery; a last-resort exception filter reports internal errors and logs
    them to `%LOCALAPPDATA%\ImageCrat\Preview\crash.log`.
  - Hidden `--snapshot <png>` flag renders the window to PNG (screenshots and a GUI smoke test in the build VM, whose
    SSH session has no compositor: only the client area is captured there). `windows/screenshots.ps1` takes a set.
- **`imagecrat-cli.exe`** (`Sources/ImageCratCLI`, portable): `selfcheck`, `info`, `composite`, `brushes`,
  `make-samples`, `--version`.
- **`ImageCratWinSupport`** (portable): file loading, the self-check battery, synthetic sample files, build info.
- **Core additions:** `PSDFile` (portable PSD/PSB structure reader: header, resources, layer records and kinds,
  channel decoding raw/RLE/ZIP, the image-data composite in 8/16/32-bit RGB, grayscale, CMYK, Lab, indexed and
  bitmap) and `PSDSimpleWriter` (layered 8/16-bit PSD/PSB writer for tests and samples), with
  `Tests/ImageCratCoreTests/PSDFileReaderTests.swift` (69 tests in all on Windows).
- **Building:** `scripts/build_windows.sh` (Mac) syncs to the VM and runs `windows/build.ps1`, which builds both
  architectures from the one Arm64 toolchain (its Windows SDK has x86_64, aarch64 and i686 libraries; the x64 runtime
  DLLs come from the toolchain's `Redistributables\6.3.3\rtl.amd64.msm`, unpacked by `windows/extract-msm.ps1`),
  links icon/manifest/version resources, bundles the needed Swift and MSVC runtime DLLs (found by walking
  `dumpbin /dependents`), runs the self-check and a GUI smoke test with `PATH` reduced to the Windows folders, and
  makes Inno Setup installers (`windows/ImageCratPreview.iss`) and portable zips in `dist/windows`.
- **Not yet:** code signing (SmartScreen warns), editing, recompositing layers, colour management, `.imagecrat` files
  (needs LZFSE).
